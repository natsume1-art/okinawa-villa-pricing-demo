# 宿泊価格自動算出・調整システム（デモ / ポートフォリオ用）

沖縄のヴィラ運営における「担当者依存の価格設定」からの脱却を目的とした、
スクレイピング×ルールベースによる宿泊価格自動算出パイプラインのデモ実装です。
実際の募集案件の応募実績として提示するために、要件を模したミニマム構成で作成しました。

## 構成

```
scraper.py         周辺相場（競合ヴィラ料金）の収集。fixture解析 / 実URL取得の両対応
occupancy.py        予約データ（CSV）から日付ごとの稼働率を算出
pricing_engine.py   曜日・季節・稼働率・リードタイム・周辺相場を加味した価格算出ロジック
notifier.py          算出結果の通知・確認レポート生成（コンソール / Slack Webhook）
ota_connector.py     サイトコントローラー（ねっぱん！等）への価格反映インターフェース（スタブ）
main.py              パイプライン全体のオーケストレーション（CLI）
scripts/             デモ用サンプルデータ生成
tests/               pytestによる価格ロジックの単体テスト
```

## 実行方法

```bash
cd pricing-automation-demo
pip install -r requirements.txt

# サンプルデータ生成（初回のみ）
python scripts/generate_sample_fixtures.py

# 通知・確認モード（既定）
python main.py

# OTA連携まで実行（dry-run。実APIは未接続のためログ出力のみ）
python main.py --mode push

# テスト実行
pytest tests/
```

## 出力イメージ

```
=== 価格改定提案レポート（確認用） ===
2026-10-11 | 現行 18,000円 ▲ 提案 20,300円 (+12.8%)
2026-10-16 | 現行 18,000円 ▼ 提案 16,700円 (-7.2%)
...
※本レポートは確認・承認用です。反映するにはOTA連携（--mode push）を実行してください。
```

## 価格算出ロジックの考え方

`config.py` にパラメータを外部化しており、代表者・コンサルタントとの
要件定義を通じて数値を継続的にチューニングできる設計にしています。

1. **季節倍率**：夏季ハイシーズン／春秋の準ハイシーズン／通常期
2. **曜日倍率**：金・土曜日は倍率アップ
3. **稼働率連動（デマンドプライシング）**：稼働率が高いほど値上げ、低いほど早期割
4. **リードタイム調整**：直前（3日以内）の在庫は割引、早期予約（60日以上前）も割引
5. **周辺相場ガードレール**：算出価格が競合相場の85%〜115%を超える場合はクランプし、
   相場から極端に乖離した価格設定を防止

## 案件要件との対応

| 募集要件 | 対応箇所 |
|---|---|
| スクレイピング・外部API連携・データ収集/解析の開発経験 | `scraper.py`（HTML解析、実URL取得にも切替可能）、`occupancy.py` |
| 料金・予約情報に関連するシステムの自動連携実績 | `pricing_engine.py`（価格算出）＋`ota_connector.py`（OTA反映インターフェース） |
| 要件定義の経験 | 本README、`config.py`のパラメータ設計（意思決定をコードでなく設定値に外部化） |
| まずは通知・確認ベースの半自動運用 → 将来的にOTA自動反映へ拡張 | `notifier.py`（現行運用）と`ota_connector.py`（拡張ポイント）を分離した設計 |

## 本番移行時に必要な作業（未実装・要すり合わせ事項）

- 実際の競合サイト／OTAのスクレイピング対象・利用規約確認、アクセス頻度のレート制限
- ねっぱん！等サイトコントローラーとの連携方式のベンダー折衝（REST API / CSV / SFTP）
- 稼働率・予約データの実データソース（PMS）への接続
- 価格改定の承認フロー（誰が・どのタイミングで承認するか）の要件定義
- 異常値検知・アラート（想定外の急騰/急落を自動反映しないためのガードレール強化）
